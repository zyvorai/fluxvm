Zyvor·FluxVM
Live migration

Move the VM. Keep its connections.

Established flows travel with the VM: the kernel conntrack table is exported from the source and restored on the destination, but only if the policy and identity match exactly.

01 · SOURCE

Quiesce

New flows are dropped at the edge (migration-quiesce); established ones keep running. ARP/DHCP/NDP still pass.

02 · SOURCE

Export

Conntrack snapshot with the VM identity, schema and committed policy fingerprint.

03 · WIRE

Move RAM + state

QEMU live migration, optionally mTLS on the data stream.

04 · DESTINATION

Verify & restore

Fingerprint must match, or the restore is refused. Entries go straight into the pinned map in-process: no helper per entry.

05 · DESTINATION

Resume

The edge opens; flows continue. On failure or cancel the source resumes automatically.
